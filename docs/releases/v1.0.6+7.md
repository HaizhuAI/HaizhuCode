# v1.0.6+7 — Custom-provider limits & thinking tiers

Custom-API imports no longer lie about the model's context window, and
thinking models get the five-step effort picker.

## Root cause

`CustomProviderSpec.toConfigJson` wrote `models: {<id>: {}}` — empty
entries. Verified against a real `@opencode/cli@2.1.1` server: a blank
model entry is served with `limit: {context: 200000, output: 32000}`
and an auto-injected three-tier variant list. Any 32k/128k/512k/1M
endpoint therefore showed 200k in the usage meter and lost two effort
tiers.

## What the form writes now (verified on the live server)

```jsonc
"models": {
  "m-think": {
    "limit": {"context": 512000, "output": 64000, "input": 448000},
    "reasoning": true,
    "options": {"reasoningEffort": "medium"},       // optional default
    "variants": {
      "none":   {"reasoningEffort": "none"},
      "low":    {"reasoningEffort": "low"},
      "medium": {"reasoningEffort": "medium"},
      "high":   {"reasoningEffort": "high"},
      "xhigh":  {"reasoningEffort": "xhigh"}
    }
  }
}
```

`/api/model` echoes this back as `limit {context,input,output}` and
`variants [{id, settings:{reasoningEffort}}]` — the values the app's
meter and variant picker already consume. All five tiers survive;
each carries its `reasoningEffort` into the request body.

## Changes

- `CustomProviderSpec`: `contextLimit`/`outputLimit`/`inputLimit`,
  `reasoning`, `defaultEffort`; `toConfigJson` writes `limit`,
  `reasoning`, `variants` (5 tiers), `options.reasoningEffort`.
  Validation: limits positive; context+output required as a pair (the
  server's `limit` object has no half-state); input ≤ context; effort ∈
  the five tiers.
- Custom-API sheet: three numeric fields (context / max output / max
  input-optional), a **Thinking levels** switch, and a **Default
  effort** picker (Server default + five tiers).
- `hz provider add`: `--context N --output N [--input N] --thinking
  [--effort T]` writes the identical shape; unpaired context/output is
  rejected.
- l10n: en + zh for all new strings (es/ar/ja/pt/ru fall back to en).
- Live e2e (`test/_live_e2e_test.dart`) now polls past the fs/write
  hot-reload and asserts the catalog serves `limit` + five variants —
  passes against a real 2.1.1 server.
